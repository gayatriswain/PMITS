# ProManage — Frontend

Marketing site for **ProManage IT Solution**: 30+ routes (services, hire-developer pages, SEO, blog, testimonials, career, …) built with Next.js. Content, SEO, menus, settings and every form submission are handled by the CMS in [`../cms`](../cms) (Next.js + MongoDB, admin at `localhost:4000/admin`). See the [root README](../README.md) for setup.

> **Read this first — Next.js version.** This repo runs **Next.js 16.3.4 + React 19.2**, which has breaking changes vs. older Next.js. [`AGENTS.md`](AGENTS.md) (auto-generated by `next dev`) tells you to read the bundled docs in `node_modules/next/dist/docs/` before writing framework-level code. Don't rely on memory of Next 13/14 APIs (e.g. layouts use the global `LayoutProps<"/">` type, see [`app/layout.tsx`](app/layout.tsx)).

## 4. How a page is built (and connected to the CMS)

A page is still a stack of coded section components. Each route wraps the stack so the CMS can control it:

```tsx
// app/marketing-growth/local-seo/page.tsx
const staticMetadata: Metadata = { title: "…", description: "…" };
export async function generateMetadata() { return cmsMetadata("/marketing-growth/local-seo", staticMetadata); }

export default function Page() {
  return (
    <main>
      <JsonLd path="/marketing-growth/local-seo" />
      <CmsSections path="/marketing-growth/local-seo" sections={[
        ["hero", <LocalSeoHero key="hero" />],
        ["faq", <FAQSection key="faq" />],
      ]} />
    </main>
  );
}
```

- `CmsSections` applies the published order and visibility, and gives every section its CMS content through `SectionContentProvider` ([`components/cms/SectionContent.tsx`](components/cms/SectionContent.tsx)). Pages with a fixed layout (home, location, website development, hosting) use `<CmsSlot path k>` around each section instead.
- **All section content is editable.** Inside components, text is written as `{$t("FileName__t12", "Original text")}` (the hook is `const $t = useCmsText()`), and data lists as `const items = useCmsData("FileName__items", items__cms)`. Without CMS edits these return the original values, so output is identical. **When you edit a component, keep this pattern:**
  - Change the default text inside `$t(…)` freely.
  - Don't reuse a key for different text.
  - Text you add later becomes editable after `cd ../cms && npm run content:codemod -- --apply && npm run registry`.
- Sections that read a CMS collection have a small server wrapper plus a `…View` client component: `ClientStories` (Testimonials) and `ProjectsCarousel` (Portfolio). `CareerOpenPositions` receives `jobs` from `app/career/page.tsx`. The header's services menu merges in Content → Services (`app/layout.tsx`).
- If the CMS is unreachable (3-second timeout), every page renders exactly as coded, using the static metadata and built-in content.
- Pages are static, refreshed every 5 minutes, and refreshed immediately when something is published in the CMS (tag revalidation through `/api/revalidate`).

**To add a page:**
1. Create the sections under `app/components/<page-folder>/` and the route under the right group folder.
2. Wrap the sections as shown above.
3. Run `cd ../cms && npm run registry && npm run seed` so the page appears in the admin.
4. Add the page to the menus in *Admin → Navigation*.

[`Container`](app/components/shared/Container.tsx) is `mx-auto w-full max-w-[1440px] px-6`.

### Known routing gaps

Many buttons link to `/contact`, and the header CTA defaults to `/quote`. Neither page exists yet (404). Either build them or change the links; the header CTA link can be edited in *Admin → Settings*.

## 5. Styling & design conventions

- **Type system** (in `globals.css`): `h1` = Playfair Display, `h2–h6` = Geist, body = Inter, buttons inherit. Utility `.font-playfair` forces Playfair. Components can override per element (the UI/UX page uses **Newsreader** for headlines via `next/font` inside the component).
- **Brand colours** are used as arbitrary values, not theme tokens: teal `#0d9488` (accent), navy `#0c1e3d` (text/dark), plus slate neutrals. Dark sections use `#050b18`.
- **Shared keyframes** in `globals.css`: `draw-path`, `fade-up-in`, `soft-pulse-ring`, `ticker-scroll(-x)`, `slide-fade-in`, `cursor-float`, `orbit-spin`. Component-specific keyframes are defined in a `<style>` tag inside the component (e.g. `uiuxShine`, `apprFlow`).
- Responsive: mobile-first, sections stack on small screens; fancy absolute-positioned compositions are `lg:`/`xl:` only, with a plain grid fallback below.

### Animation conventions

- Entrance: `initial` + `whileInView` + `viewport={{ once: true }}` with `delay: idx * 0.1`.
- Loops: framer `animate={{ y: [0, -8, 0] }}` + `repeat: Infinity` for floats; CSS `animate-[…]` for spins/flows.
- Always respect reduced motion: `useReducedMotion()` → skip loops / render the final state.

### Gotchas we hit (please read before touching animated components)

1. **framer-motion overrides CSS `transform`.** If a `motion.*` element animates `y`/`rotate`, a Tailwind class like `[transform:perspective(…)_rotateY(…)]` is silently replaced. Put 3D tilt in `style={{ transformPerspective, rotateX, rotateY, rotate, skewX }}` instead. (Tailwind v4 `-translate-x-1/2` is safe — it uses the separate CSS `translate` property.)
2. **`pathLength` + `vectorEffect="non-scaling-stroke"` don't mix.** Dashes are measured in screen px while `pathLength` is normalised, so the draw animation stops partway. Don't use `non-scaling-stroke` on a path that animates `pathLength`. (It *is* fine on dash-offset "flow" paths.)
3. **`<Container className="max-w-7xl">` does not narrow it** — `max-w-[1440px]` is already applied and wins. Put an inner `max-w-[…] mx-auto` div if you need a narrower column.
4. **`next/image` with `fill`** needs a positioned parent.
5. `whileInView` content stays at `opacity: 0` until the element actually intersects the viewport — relevant when taking screenshots (see §8).

## 6. Case study: the UI/UX Design page (`/design-innovation/ui-ux-design`)

Most recent work. Six sections, each reference-matched to a design mock. Files: `UiUxHero`, `UiUxApproach`, `UiUxWhatWeDo`, `UiUxWhyUs`, `UiUxClientStories`, `UiUxContactCTA` (+ `UiUxGlassTile3D`).

### 6.1 Hero — [`UiUxHero.tsx`](app/components/ui-ux-design/UiUxHero.tsx)

Layout: a ≤1180 px "stage" (`lg:h-[580px]`): centred headline/CTAs, glass design-system card on the left, phone on the right, 3D tile at the bottom-centre, a spline connecting the three, wireframe "floor sheets", and a 4-step process bar below. On `<lg` the absolute composition collapses to a vertical stack (`lg:contents` on the wrapper lets children be absolutely positioned relative to the stage on desktop only).

- **Background:** `public/ui-ux-hero.webp` via `next/image fill priority` (base colour `#e9eff7` behind it), plus two blurred teal/sky blobs that drift.
- **Headline:** Newsreader, per-word masked slide-up (`RevealLine`), second line is an italic teal gradient with a CSS shine (`uiuxShine`).
- **Mouse parallax:** `onMouseMove` → two `useMotionValue`s → `useSpring` (stiffness 60) → `<Parallax depth={n}>` wrappers apply `x/y` offsets (negative depth = moves opposite, giving depth). The same springs are passed into the 3D tile.
- **Layered transforms:** each object is *outer positioned div → entrance motion.div → Parallax → float motion.div (→ static tilt via `style`)*. Keeping each concern on its own element avoids the transform-override gotcha.
- **Inward 3D tilt** (matches the mock): left card `rotateY 22, rotateX 8, rotate −3, skewX 5`; phone `rotateY −22, rotateX 6, rotate 7` (both `transformPerspective: 900`). Positive `rotateY` on the left card / negative on the phone turns both toward the centre.
- **Spline:** SVG `preserveAspectRatio="none"` path drawn with `pathLength`, plus a dashed glowing "energy" path animated by CSS (`uiuxFlow`); end nodes are HTML dots at `%` positions (so they don't stretch).
- **Auto-cycling UI:** phone slides every 3.4 s (`AnimatePresence`, with `01 — 03` counter/progress), colour swatches every 2.2 s (the "Aa" glyph takes the swatch colour; `layoutId` ring follows), process-bar step every 2.8 s with a progress underline. All stop under reduced motion; all are clickable.

### 6.2 Approach — [`UiUxApproach.tsx`](app/components/ui-ux-design/UiUxApproach.tsx)

5-step strip joined by a sine-like wave.

- **Geometry:** one SVG (`viewBox 0 0 1000 100`, `preserveAspectRatio="none"`) behind a `grid-cols-5` row. Each column is 20 % wide, so badge centres sit at x = 100/300/500/700/900 in SVG units. Crests (`y=68`) go *behind the lower part of each badge*; troughs (`y=86`) lie between badges. The badge row is a fixed `h-[72px]`, so badge centre ≈ y 36 px and the wave passes below it.
- **No collisions (explicit requirement):** step numbers are absolutely positioned `right-[76%]` of their column (well left of the badge, above the wave) and the teal dot under each badge has `mt-5` so it sits below the trough.
- **Animation:** wave draws once (`pathLength`), then a glowing dash travels along it (CSS `apprFlow`). An "active step" index advances every 2.2 s *only while the strip is on screen* (`useInView`) and pauses on hover: active badge scales/lifts with a ring + halo ping, number turns teal, icon wiggles, accent line widens.
- "Real impact." is Caveat, revealed left→right with `clipPath`, then an underline swoosh draws.
- The strip's decorations (dot grids, faint circle behind step 5) are absolutely positioned **inside** the strip wrapper, and the scroll container has `pt-10` so the active-badge halo isn't clipped by `overflow-x-auto`.

### 6.3 Contact CTA — [`UiUxContactCTA.tsx`](app/components/ui-ux-design/UiUxContactCTA.tsx)

Dark section (`/uiux.webp`, 1802×873) with four cards **anchored to the glowing orbs in the artwork**.

- **Problem:** `object-cover` crops the image differently at every viewport, so percentage positions on the *section* drift off the orbs.
- **Solution — "cover box":** a container with `container-type: size`, and inside it a box that mimics `object-cover` using container-query units:
  ```ts
  width: "max(100cqw, calc(100cqh * 1802 / 873))"; aspectRatio: "1802 / 873"; // centred with translate(-50%,-50%)
  ```
  The `<Image fill>` and the card layer both live inside identical cover boxes, so `left/top: %` map to *image* coordinates and always land on the same pixels as the art.
- **Orb coordinates** (% of the 1802×873 image): 01 → (39.7, 62.8), 02 → (53.8, 51.8), 03 → (64.0, 40.6), 04 → (71.7, 38.3). Edit the `orb` field of each entry in the `cards` array.
- Each anchor = ping ring on the orb + growing stem + floating card (`bottom-[40px]`, centred, `w-[170px]`).
- **No-overlap rules:** the section is `lg:min-h-[1100px]` and the header is compact so card 01 clears the trust badges; cards are 170 px so 03/04 (orb spacing ≈ 175 px) don't touch. The orb layer is **`xl:` (≥1280 px) only** — below that the image's right side is cropped away, so the original 2-column card grid is shown instead.

### 6.4 3D glass tile — [`UiUxGlassTile3D.tsx`](app/components/ui-ux-design/UiUxGlassTile3D.tsx)

A real-time 3D "frosted teal glass" slab with an engraved pen-tool icon (replaces a flat CSS cube).

- Loaded with `next/dynamic(..., { ssr: false })` from the hero, so three.js stays out of the initial bundle and SSR. Props: `mx`, `my` (the hero's parallax motion values), `reduce`, `className`.
- **Scene:** `RoundedBox` shell (`MeshPhysicalMaterial` with transmission, clearcoat, teal attenuation) + a smaller emissive inner core for depth + a top "sheen" plane + the icon plane. Lighting: ambient + directional + a teal under-light + an orbiting point light for the travelling highlight. Reflections come from `<Environment>` with `Lightformer`s (offline — **no HDR download**).
- **Icon:** painted onto a 512² `CanvasTexture` each frame — the bezier curve is split with de Casteljau to "draw" it, then handles/anchors pop, hold, fade, loop (7 s cycle). An offset light copy under the dark stroke gives the engraved look.
- **Motion:** `useFrame` — float (sin), yaw/pitch drift, pointer parallax (`THREE.MathUtils.damp`), hover scale, intro scale-up from 0.55.
- **Floor glow** is plain CSS blurred ellipses *outside* the canvas (an in-canvas glow plane got hard-clipped at the canvas edge).
- **Safety:** IntersectionObserver switches `frameloop` to `"never"` off-screen; `"demand"` under reduced motion; an error boundary falls back to a flat tile if WebGL is unavailable.

### 6.5 Other sections & spacing

`UiUxWhatWeDo` (animated 3D layers + 6 service cards + stats), `UiUxWhyUs` (4 pillars around a central 3D stack + bottom pill), `UiUxClientStories` (carousel with multi-device mockups) were built earlier. ## 7. Forms → CMS

Every form posts to the CMS (`NEXT_PUBLIC_API_URL`). Submissions appear under *Admin → Leads / Proposals / Applications*, and the team gets an email alert when SMTP is configured.

| `POST /api/leads` (legacy payload) | `ArVrCTA`, `CustomDevStartProject`, `AiSeoStrategy`, `LocalSeoContact`, `HireShopifyContact`, `HireCakePhp*`, `MagentoProposal`, `BigCommerceContact` |

Every form has a hidden honeypot field ([`components/cms/Honeypot.tsx`](components/cms/Honeypot.tsx), or a `website` field in the older forms). Keep it when you build a new form.

## 8. Verifying UI changes

- Type-check + lint the files you touched: `npx tsc --noEmit` and `npx eslint app/components/YourFile.tsx`.
- Look at it in a real browser at **1280, 1440 and ~390 px** wide. For layout checks, headless Edge/Chrome works:
  ```powershell
  msedge --headless --disable-gpu --window-size=1440,1000 --virtual-time-budget=15000 --screenshot=out.png http://localhost:3000/design-innovation/ui-ux-design
  ```
  Tips: warm the route first (`curl` it) or the screenshot catches the *Compiling…* state; for WebGL add `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`; sections below the fold render via `whileInView`, so render them on a temporary route (and delete it afterwards) — and note scroll-triggered animations occasionally don't fire in headless mode, which looks like "blank section" but isn't a code bug.
